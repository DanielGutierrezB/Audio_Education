## 1. Resemble Enhance — más suave (commit `ecc53a4`)

**Archivos:** `src/python/enhance.py`, `main.js`, `renderer/index.html`,
`renderer/js/app.js`.

### Qué cambió en los presets

| Preset            | lambd antes → ahora | tau antes → ahora | nfe |
|-------------------|---------------------|-------------------|-----|
| `ultra_subtle` (NUEVO, default) | — → 0.98 | — → 0.15 | 128 |
| `subtle`          | 0.95 → 0.97         | 0.30 → 0.20       | 128 |
| `light`           | 0.85 → 0.90         | 0.40 → 0.30       | 128 |
| `balanced`        | 0.70 → 0.78         | 0.50 → 0.40       | 128 |
| `strong`          | 0.50 → 0.60         | 0.50 → 0.45       | 128 |
| `_fast` variants  | igual con nfe=64    |                   |     |

- `lambd` más alto = más fiel al original (menos regeneración).
- `tau` más bajo = menos estocasticidad → menos artefactos / flanger entre chunks.
- `nfe=128` se mantiene como default (max consistencia entre chunks).

### Bug pre-existente que descubrimos aquí

El UI (`main.js` + `renderer/index.html`) listaba presets `light`,
`balanced`, **`broadcast`**, **`aggressive`**. Pero el `enhance.py` actual
NO tiene esos dos últimos. Es decir, si el usuario seleccionaba "Broadcast"
en el dropdown, el Python rechazaba el preset y todo el paso fallaba en
silencio. Sincronizamos UI ↔ Python.

## 3. EQ adaptativo (sesión actual, sin commit aún)

**Archivos:** `src/voice-profile.js` (NUEVO), `src/analyzer.js`, `src/pipeline.js`.

Pedido: que el EQ se adapte al tipo de voz y atenúe frecuencias resonantes.

### Cómo funciona

1. **`src/voice-profile.js`** — módulo nuevo, sin dependencias externas.
   - Decodifica los primeros 60 s del archivo a mono @ 8 kHz con ffmpeg.
   - FFT in-house (radix-2 Cooley-Tukey, ventana Hann, FFT_SIZE=4096,
     hop=2048). ~65 ms por archivo.
   - **Detecta el f0 dominante** (pitch fundamental) buscando el bin más
     fuerte en 70–320 Hz, con interpolación parabólica para precisión sub-bin.
   - **Detecta picos resonantes** en 180–900 Hz: comparados contra el
     median local en 1/3 octava, exigiendo prominencia ≥ 4.5 dB. Hasta 3
     notches, separados al menos 1.25 octavas.
   - Clasifica la voz: `deep_male` / `male` / `high_male` / `low_female`
     / `female` y devuelve `bodyBoostHz` y `hpfHz` adaptados.

2. **`src/analyzer.js`** — llama a `profileVoice()` y guarda en
   `rec.settings`:
   - `hpfFrequency` ahora depende del f0 (60–90 Hz según voz) y de
     reverb (sube ~20 Hz si hay reverb).
   - `bodyBoostHz` (600–1000 Hz según voz).
   - `dynamicNotches`: array `[{freq, q, prominenceDb}, ...]`.

3. **`src/pipeline.js#buildEqChain`** — antes era una curva fija. Ahora:
   - Mantiene HPF, +1 dB @ 150, −1.5 dB @ 250 (cuts genéricos).
   - **Inserta los notches dinámicos** (`equalizer width_type=q`) entre
     el cut de 250 Hz y el body boost.
   - Body boost se mueve a `bodyHz` (de 800 default a 600–1000 Hz según voz).
   - Si un notch cae sobre el body boost, el body boost se sube 1/3 oct.

### Validación

Smoke test contra el archivo de Jorge (`01_2601_arrays-avanzados-js...`):
- Detectó **f0 ≈ 129 Hz, voz "male"**.
- HPF: 80 → 70 Hz.
- Body boost: 800 → 700 Hz.
- Notches: ninguno (audio limpio).

Smoke test inyectando resonancias artificiales en 350 y 550 Hz:
- Detectó **354 Hz** y **555 Hz** (precisión <1%).
- Q estimado: 16.5 y 18.9 (correcto, eran resonancias estrechas).
- Prominencia: 5.5 y 5.2 dB.

## 5. Resemble Enhance — instalación (en progreso)

`pip3 list` confirmó que **resemble-enhance NO estaba instalado** en
ningún Python del sistema. Por eso Resemble nunca regeneraba: el subprocess
fallaba con "module not found", el pipeline lo manejaba con el `try/catch`
y seguía sin él. Confirmado en log: `"Resemble Enhance failed,
continuing without regeneration"`.

### Plan de instalación (venv aislado)

- Path: `~/.audiopro-venv/`
- `resemble-enhance` exige `torch==2.1.1` exacto.
- Python 3.12 + arm64 → no hay wheel de torch 2.1.1 → falla.
- **Solución:** Python 3.10 vía pyenv (Homebrew python@3.10 tiene un bug
  de `expat` en macOS 25.2: `Symbol not found:
  _XML_SetAllocTrackerActivationThreshold`).
- Instalar `pyenv`, `pyenv install 3.10`, recrear venv, instalar
  `resemble-enhance soundfile`.
- Setear `AUDIOPRO_PYTHON=~/.audiopro-venv/bin/python` en el entorno
  cuando se lance la app (o documentarlo en README).
